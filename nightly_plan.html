Nightly autonomous-run plan — bee counter

Plan for unattended overnight Claude sessions to improve the counters, bring up C2–C4, and tidy the repo — with measurable goals and hard guardrails. Draft for review; nothing autonomous launches until the prerequisites + mechanism are confirmed.

Guiding principle

Every nightly task must have a number that goes up (or a binary that flips green) and a hard stop. No open-ended "make it better." A session picks the top backlog item, does it, scores it, commits if it's an improvement, logs the result, stops.

Prerequisites (must exist before a camera can be tuned measurably)

Measurability needs ground truth. C1 has it (51 manual IN labels). For each other camera you want worked on overnight, provide — via the viewer — : 1. Crop (/microscope/<cam> → edit crop) → configs/microscope.yaml. 2. Entry-zone polygon (/microscope/<cam> → draw, click save) → configs/entry_zones.yaml. ← C1's is currently NOT saved; redraw + save. 3. GT entry labels (/label/<cam> → mark each IN) → ground_truth_labels.jsonl. Without GT, the night can only produce counts, not verify/tune them.

Measurable goals

Goal Metric Target
C1 count (shipped) predicted IN / GT 51 within ±10% — met (52)
C1 per-event quality temporal F1 (±15f) ≥ 0.80 (now 0.76) — stretch
C2–C4 count (per cam) predicted IN / GT within ±20% (needs GT)
Repo health pytest + ruff green every session
Reproducibility one command per camera regenerates count + score yes

Task backlog (prioritized; each: metric · done-when · stop-after)

  1. C1 — your "any bee that enters the marked polygon" counter. Use the saved entry-zone polygon + FT detector + zone-entry counter. Metric: F1 / ratio vs 51. Done-when: F1 > 0.76 or documented why not. Stop-after: 3 tuning rounds.
  2. C1 — per-hole occupancy (no tracking). Per dark hole, detect "bee present → absorbed" changepoints on the FT detector (sidesteps track fragmentation). Metric: F1/ratio. Done-when: beats motion or ruled out. Stop-after: 1 build + 3 tunes.
  3. C2–C4 bring-up (per camera with prereqs): run the motion pipeline, score vs GT, tune ROI/zone/MOG2. Metric: ratio within ±20%. Stop-after: 1 sweep/camera.
  4. Per-camera detector fine-tune (if box labels provided): finetune_c1.py generalized per camera. Metric: recall + count. Stop-after: 1 train + 1 eval.
  5. Repo organization: README + architecture doc; group scripts; prune/retire dead-ends into a clear archive; ensure every script has a usage docstring. Done-when: README exists, ruff+pytest green, no orphan scripts.

Per-session protocol (autonomous Claude)

  1. Read decisions.md + this plan + git log to see state.
  2. Pick the highest-priority backlog item whose prerequisites are met.
  3. Implement in a branch; run uv run pytest -q and uv run ruff check ..
  4. Score against GT with compare_to_gt.py; append a bakeoff row.
  5. If improved & green: commit (conventional message). If not: write the negative result to decisions.md (so the next session doesn't repeat it) and move on.
  6. Append a dated entry to nightly_log.md; Telegram a 1-line summary.

Guardrails (non-negotiable)

  • Never regress: a commit requires pytest + ruff green and no GT-score drop on C1.
  • Bounded loops only (max iterations / wall-clock deadline per task).
  • After 3 failed attempts at one approach → log to decisions.md, switch task.
  • Never delete data/ or *labels*.jsonl. Never commit weights/data (gitignored). Token budget per session (set at launch).
  • Work camera-by-camera; verify after each before starting the next.

Launch mechanism (to confirm)

Options (pick one): (a) a LaunchAgent/cron running claude -p "<session prompt>" hourly that executes the protocol; (b) /schedule cloud routine; (c) a single megatask plan. Recommend (a) with a small wrapper that injects the protocol + a per-run token cap, logging to nightly_log.md.
