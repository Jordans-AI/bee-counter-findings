C2 / C3 entry-counter bring-up — UNVERIFIED counts

Extends the C1 motion entry-counter to cameras C2 and C3, the two cameras that now have both a saved entrance crop (configs/microscope.yaml) and a hand-drawn entry polygon (configs/entry_zones.yaml). C4 is not brought up yet — it has a crop but no drawn polygon.

Method (identical to shipped C1)

ROI crop → CLAHE → MOG2 motion → Hungarian tracker → VanishEntryCounter. A bee is counted IN when a track arrives at the entrance from any direction and disappears into it. The entrance region is the hand-drawn polygon for that camera (use_drawn_zones: true), not C1's auto dark-mask. See src/beecounter/count/vanish_entry.py.

The motion/tracker/dedup parameters are inherited verbatim from C1's tuned config as a sensible starting point. They are not tuned per camera, because neither C2 nor C3 has manual ground-truth labels to tune or score against.

Results (best-effort, UNVERIFIED — no ground truth)

Camera Config predicted IN blobs notes
C2 configs/c2_entry.yaml 68 10768 sparse / sky background; bright-rail lip
C3 configs/c3_entry.yaml 41 46543 dense crowd at entrance (hardest case)

⚠️ These counts are not validated. Without per-camera GT they cannot be confirmed within any error band, and the C1-inherited parameters are likely not optimal here. Treat the numbers as a pipeline-works smoke test, not a measured count. C3's far higher blob count (46k vs 10k) reflects the dense crowd — many overlapping bees that the simple centroid tracker will merge or fragment, so its count is the least trustworthy.

Reproduce

uv run python scripts/run_c1_entry.py --config configs/c2_entry.yaml --annotate
uv run python scripts/run_c1_entry.py --config configs/c3_entry.yaml --annotate

Outputs land in results/runs/entry_<cam>_<ts>/<cam>/ (events.jsonl, counts.json, config.yaml, annotated.mp4 — all gitignored).

To verify / make these real

  1. Label IN events for C2 and C3 in the viewer (/label/<cam>) → ground_truth_labels.jsonl (currently C1-only, 51 IN).
  2. Score with scripts/compare_to_gt.py --camera C2 --events <run>/events.jsonl.
  3. Tune ROI / polygon / MOG2 / dedup per camera against that GT, as was done for C1.
